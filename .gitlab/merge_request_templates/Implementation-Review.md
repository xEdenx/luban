## 变更依据

- 变更 ID / 等级 / 等级确认人：
- 分阶段确认记录（L1/L2），或已批准 Spec MR（L3）：
- 已确认 Spec/Mini-Spec 及精确版本：
- 技术/专项确认（适用时）：
- 本次实现范围与变化：

## 可执行验收

- 验收记录内部链接：
- 被测代码版本与工作区状态：
- 实际运行命令、退出结果、原始报告：
- AC 覆盖、人工验收与未验证项：
- Converge 检查结果及剩余工作：
- 测试后变更与重新执行情况：

## Reviewer 与合并人核对

- [ ] 代码与已确认业务语义一致，测试断言有效。
- [ ] 必需验证实际执行，没有把跳过、旧报告或零测试当成成功。
- [ ] 被测版本与最终 MR head 对应，后续实现变化已重跑相关验证。
- [ ] 必要人工验收完成；风险、例外与补全期限明确。
- [ ] 长期设计/接口/ADR 已按影响同步；交付后 Spec 保留为历史。

Reviewer 与审核结论：

最终交付通常由另一位开发者审核；如有例外，记录原因、确认人和替代复核方式。

团队无法自动触发 CI 时，由合并人按此记录执行人工核验；模板本身不能阻断合并。

# 验证案例清单

这些案例用于工作电脑按步骤验证。当前个人电脑原生探针结果见原生核验表，AC 检查器已用虚构报告与临时 Git 仓库自检；工作电脑未执行项仍保持 unverified。

| 案例 | 操作 | 预期与判定边界 |
|---|---|---|
| V0-01 材料版本 | 记录下载 tag/commit/归档来源 | 能明确正在验证哪一版，不依赖聊天历史 |
| V0-02 运行环境 | 检查 Python、Git、批准的软件来源 | 满足时进入 CLI 验证；否则 blocked，仍可阅读材料 |
| V0-03 客户端身份 | 记录插件基线与 Qoder 产品版本 | 能区分上游/自研、CLI/IDE/App |
| V0-04 GitLab 能力 | 核查实际版本、MR 权限和审批功能 | 不把可选 approval 误当强制审批 |
| V1-01 原生初始化 | 隔离空项目运行 generic Skills 初始化 | 产物正确、脚本引用存在；不是模型执行成功 |
| V1-02 Bug / Lean | 安装官方组件并检查生成内容 | 原生命令/覆盖实际注册；不是业务案例通过 |
| V1-03 gate 暂停 | 虚构 gate 不提供 verdict | 返回 paused，不执行下一步 |
| V1-04 gate 恢复/拒绝 | 虚构 gate 分别批准、拒绝 | 分别继续/终止；不代表可信身份授权 |
| V2-01 指令发现 | 两客户端分别发现或引用入口 | 记录 native/thin-adapter/manual-reference |
| V2-02 澄清与确认 | 提供有一个未知规则的虚构需求 | Agent 提出问题，不静默猜测为已批准 |
| V2-03 活跃变更 | 切换到新需求并保留历史 Spec | 使用当前意图，旧 Spec 只作参考 |
| V2-04 跨工具接力 | 在另一客户端继续同一活跃变更 | 正确读取 Spec、Plan、Tasks 与未完成验证 |
| V3-01 L0 正例 | 有 Mini-Spec 的局部修复 | 现有测试与人工 Review 可追溯 |
| V3-02 L1 正例 | 人工确认 Spec/AC 后实施 | AC、实际测试和最终审核对齐 |
| V3-03 缺 AC 映射 | 删除一个必需 AC 的关联 | 检查器或人工必须发现；分别记录发现者 |
| V3-04 未执行/跳过 | 让必需测试不执行或跳过 | 原型必须失败；真实工程也须验证，不凭自检声称平台拦截 |
| V3-05 旧证据 | 代码/AC 改变后引用旧报告 | 要求重新执行相关验证 |
| V3-06 脏工作区 | 被测内容包含未提交变化 | SHA 不足以标识输入；记录快照或提交重跑 |
| V3-07 未确认 / 变更后失效 | 隔离 MR 缺确认或修改关键内容 | 据实区分平台阻断与合并人发现 |
| V3-08 无记录 Chat 修复 | 直接改代码但无 Mini-Spec | Review 应要求补充意图与验证依据 |
| V4-01 L2 影响面 | 单 MR 分阶段的跨模块/接口变更 | 技术方案版本确认、兼容与集成验证齐备 |
| V4-02 新工程 | 空白业务试点建立最小架构与规则 | 不产生全量历史规格，不强制所有任务 L2/L3 |
| V4-03 L3 隔离演练 | 专项方案、预演与恢复流程 | 开发验证不等同于生产发布授权 |

案例结论只证明指定环境与范围。自动校验器尚未实现时，负例由人工发现应记录为人工能力，不把它计为自动软件门禁成功。

采用 [工作电脑结果模板](../templates/workstation-validation-record.md) 保存实际步骤与证据。实现、测试、配置、依赖、Spec/AC 或关键客户端版本变化后，重新执行受影响案例，避免无差别重复测试。

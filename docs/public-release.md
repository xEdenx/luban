# 公开发布与工作电脑迁移

状态：通用材料已按用户授权公开发布到 [xEdenx/luban](https://github.com/xEdenx/luban)，仓库可见性为 public，默认分支为 main；本地项目目录名为 luban。真实客户端、内部 GitLab 和业务工程验证仍待工作环境完成。

## 1. 公开仓库的职责

GitHub public repo 保存通用设计、已决策路线、待批准默认规则、公开来源核验、虚构验证案例和空白模板。内部 GitLab 保存业务变更、人员批准、原始测试报告、内部地址与其他公司资料。公开仓库不作为业务证据存储。

同一份通用材料应能由个人电脑审查、发布后由工作电脑下载验证。仓库文档使用相对链接，运行说明不绑定用户名、个人绝对路径或单机虚拟环境。

## 2. 发布前检查

- 审查实际将提交的文件清单与内容，不只看 .gitignore。忽略规则不能保护已经跟踪的内容。
- 不含公司代码、真实业务 Spec、内部链接、客户/人员信息、凭证、原始日志与截图。
- 不发布 work/、.venv/、private/、local-results/ 或临时上游源码；不把个人环境打包成工作电脑运行时。
- 不复制上游完整源码/Skills 作为自有成果；通过固定来源与原生安装方式复用。需要分发上游内容时另行检查许可与归属。
- 确认自己的公开材料许可、仓库名、账号/组织、可见性和维护责任。用户已指定仓库名 luban 和 public 可见性，采用已登录账号 xEdenx；LICENSE 尚未选定，本次不自行添加。
- 版本说明区分个人电脑已验证、工作电脑未验证和操作基线待批准；未运行部分不写成“支持”。
- 检查文档相对链接、Markdown 结构、版本记录和报告引用一致。

## 3. 首次发布物建议

采用一个明确版本的仓库快照及简短发布说明。下载 ZIP 可用于阅读，Git clone/checkout 可用于保留提交身份；具体方式遵守工作电脑允许的访问渠道。

首版材料至少包括主设计、实施接力、开发者 L0～L3 使用说明、操作基线、原生能力审计、GitLab 手动验收路径、工作电脑手册、验证案例、空白模板和 ADR。Bundle 不作为首次文档发布的前提。

当前还包括 team-sdlc Extension 0.1.1 源与维护者接入说明。发布说明明确“安装/注册与检查器已验证，真实模型/客户端端到端行为未验证”；不要把开发安装方式当成已完成的正式升级/分发策略。

依赖版本快照仅记录本次运行事实；它不保证其他平台解析相同结果。离线安装包/内部镜像是否需要、允许由谁提供，在工作环境预检后确定；不默认从个人环境搬运可执行依赖。

## 4. 继续讨论与冻结边界

个人电脑阶段尽量收敛团队操作基线中的审批形式、风险判定、Reviewer 职责、例外和试点规模。记录已批准值与版本，不以“没有回复”认定批准。

进入工作电脑前，应有明确的验证材料版本、逐项案例、预期、失败判定和结果模板。工作电脑反馈具体限制及证据；仅当事实改变设计前提时回到设计讨论，不重新横向选型。

## 5. 跨环境反馈

工作结果保存在内部。公开反馈只使用经批准脱敏的通用兼容问题，例如某版本无法加载某布局；不得直接附内部代码、项目路径、地址或原始报告。外部反馈是否允许以公司规定为准。

发布到 GitHub 的动作在材料审查后，按用户明确指定的账号、仓库名和授权执行。本文件不替代该发布指令。

# ADR-0002：GitLab 无自动 CI 时采用手动验收闭环

日期：2026-10-10。状态：环境前提已确认；操作细则待团队批准和现场验证。

## 背景

用户确认团队使用自部署 GitLab，无法自动触发 CI。当前个人电脑准备公开通用材料，后续受 MDM 管控的工作 MacBook 执行验证。

## 决策

不把自动流水线作为第一版前提。复用业务项目已有测试入口，人工触发运行，记录与被测版本绑定的报告，再由 GitLab MR Reviewer 核对与有权限人员合并。

用户进一步确认：L1 使用单个 MR 分阶段，先确认 Spec/AC 的具体版本，再实现，最后审核交付。最终交付通常由另一位开发者审核，特殊情况明确记录例外。L2 单 MR 分阶段并确认技术方案；L3 Spec MR + 实现 MR。风险等级由 L0/L1 模块负责人、L2/L3 技术负责人确认，降级需相应负责人留痕。平台是否能强制这些规则仍需现场验证。

AC 语义、实际报告与人工验收契约保持稳定。未来若有允许的手动/自动 Pipeline，只替换执行与证据入口。Runner、保护分支、强制审批与许可能力待核验。

## 后果

可以保留可执行验收，但缺少自动状态门禁时不能声称软件会自动阻断所有不合格合并。实际约束由平台权限和合并人操作决定。详见 [手动验收路径](../gitlab-manual-verification.md)。

个人实验结果不替代工作环境验证。公开 GitHub 不保存内部业务资料；不通过改变 MDM 配置解决兼容限制。

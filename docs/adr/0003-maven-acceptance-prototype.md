# ADR-0003：以最小 JSON 映射连接原生 AC 与 Maven 报告

日期：2026-10-10。状态：实验实现，真实工程验证后再稳定。

## 背景

用户确认首版工程为 Java 后端、Maven、Spring Boot，且团队没有自动 CI 触发。Spec Kit 原生模板已承载验收场景，但当前核验未发现把团队 AC 与本轮 Maven testcase 结果绑定的现成原生能力。

## 决策

保留原生 Spec/Plan/Tasks/Implement/Converge，仅在验收场景添加稳定 AC ID，用 acceptance.json 0.1 记录引用和精确报告选择器。早期 YAML 是未实施提案，由 JSON 取代以免新增 YAML 运行依赖。

使用 Python 3.9+ 标准库读取 Maven 默认 Surefire/Failsafe XML。正常模式在干净且有提交的业务仓库执行明确命令，记录实际版本、退出状态、输入/报告摘要与新鲜度；报告读取模式仅用于诊断。自动项通过仍需人工核验断言、测试范围、人工项与审批记录。

不增加开发工作流、测试框架、审批服务或 CI 服务；未来允许的 CI 可调用相同检查器。未确认的框架版本、自定义布局与真实客户端不预设支持。具体见 [契约](../acceptance-contract.md)与[操作说明](../../scripts/README.md)。

## 后果

可在个人电脑用虚构输入验证失败条件，在工作电脑主要验证环境兼容与真实报告。仅声明的模块/报告集合参与校验，不能自动证明整个 Maven reactor 都执行了必需测试。

本地证据不是可信审批凭证，文件时间与摘要不能防止恶意伪造。GitLab 权限、独立 Reviewer 与必要复跑负责交付核对；尚未验证这些机制在团队环境的实际强度。

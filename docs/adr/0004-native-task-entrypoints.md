# ADR-0004：通过原生 Extension 暴露四级会话入口

日期：2026-10-10。状态：用户目标已明确；实验组件可安装，真实客户端行为待验证。

## 背景

用户需要开发者提供需求文档或功能变化描述后，Agent 自动生成规范 Spec/AC，在关键节点请人确认，然后继续生成代码、执行验证并准备交付。前版操作手册把原生命令逐步交给开发者操作，没有交付可调用入口。

已核验 Spec Kit 1.1.2 Extension 可注册命令并通过 generic 输出 Skills/命令文件。官方 Workflow command 步骤依赖 Agent CLI 派发，generic 实测无法执行；Qoder CLI 不代表独立 App，Continue 自研插件也不能假定具有上游 CLI 能力。

## 决策

使用 team-sdlc Extension 注册 L0～L3 四个命令；0.1.1 补充默认 start 统一入口，开发者无需预先评级。任何入口先依据工程证据与规则下限建议等级，负责人确认、Plan/实施新发现/最终 diff 复评、Reviewer 复核；四级入口仅作建议，不能绕过。原生 Integration 负责注册/渲染，当前 Agent 会话读取统一约定并调用实际生效的原生 Specify/Clarify/Plan/Tasks/Analyze/Implement/Converge。不能嵌套调用时可读取已安装有效指令并执行，记录为 manual-reference；不复制原生流程实现。

统一入口和四个兼容入口复用一份执行参考，在业务/技术确认处暂停，已有有效确认后自动继续工程步骤。未确认规则、风险变化、环境受限或关键方案变化才请求必要输入。L1/L2 单 MR、L3 双 MR 和审批权限保持不变。

Maven 检查器唯一实现移入 Extension，标准仓库旧路径保留兼容启动器。安装后共享规则和执行脚本留在业务工程 .specify/extensions/team-sdlc/；不要求工作电脑访问个人路径。

## 后果与验证边界

已有可安装入口，开发者使用说明以“调用 + 输入 + 确认 + 功能核对”为主；安装/调试放到维护者接入说明。人工触发意味着由人启动/确认工作流，测试命令可由 Agent 执行，不要求开发者逐条键入。

Skills 是模型指令，不能独立提供可信身份或强合并门禁。安装通过不等于模型行为或客户端兼容通过；后续必须测试缺确认暂停、确认后推进、修订恢复与实际验收。正式分发仍待试点，再通过官方 Bundle 组合稳定组件。
